# 进化闸门判定表

> 每次改动部署前逐项判定。任一闸门不过,改动不部署。
> 与 conventions/evolution-gate.md 的 G1-G5 对应,本表是落地执行版。

## 五闸门

| 闸门 | 问题 | 通过条件 | 判定 |
|:---|:---|:---|:---|
| G1 问题 | 改动解决的是真实问题吗? | 有 metrics 数据证明问题存在 | ☐ |
| G2 证据 | 改动有效的证据? | A/B 对比或前后指标快照 | ☐ |
| G3 复用 | 改动是否泛化? | 不只修复单一案例,同类场景覆盖 | ☐ |
| G4 契约 | 行为契约更新了吗? | SKILL/schema/red-flags 同步修订 | ☐ |
| G5 验证 | 可以回归验证吗? | regression.json 全量通过 | ☐ |

## 五维加权(部署优先级参考)

| 维度 | 权重 | 改动前 | 改动后 |
|:---|:---:|:---:|:---:|
| 可靠性 Reliability | 25 | | |
| 可观测性 Observability | 20 | | |
| 可恢复性 Recoverability | 20 | | |
| 质量控制 Quality | 20 | | |
| 进化能力 Evolution | 15 | | |

## 判定

- 总分提升且无维度劣化 → Deploy
- 总分提升但某维度劣化 > 5 分 → 评估回滚预案后再部署
- 总分下降 → Rollback / 放弃改动
