# 回滚流程 Rollback

> 回滚回行为,不回滚状态。回滚不是失败,是设计的一部分。

## 触发条件(任一)

- 观察期内成功率较基线下降 > 5 个百分点
- 反测集出现基线没有的新失败
- 出现基线没有的人工介入需求
- 产生数据损坏或错误产出且已外发

## 步骤

1. **停止**:暂停相关 cron/触发器,防止劣化持续
2. **恢复**:从 deploy/snapshots/ 恢复最近一个通过验证的快照
3. **保留状态**:STATE.md / 记忆层不动——回滚的是行为文件
4. **记录**:把失败原因写入 baseline 已知失败 + regression.json 补一条反测
5. **恢复运行**:用旧版本重新部署,观察一个周期

## 禁止

- 在劣化版本上「再修一下」——先回滚,修复走新的进化循环
- 回滚时清理状态文件
- 触发条件满足却不回滚(沉没成本谬误)
